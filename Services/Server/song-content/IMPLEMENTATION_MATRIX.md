# 需求实现矩阵

## 已打通

- 统一歌曲实体、平台映射、内容版本、发布指针、来源、任务、审计和 RBAC 持久化。
- 首次缺失的幂等任务、租约恢复、重试、证据包、结构校验、来源覆盖、风险检查和永久保存。
- Agent 管理中的内容审核、字段差异、来源、生成记录、Token、费用、发布、下线、回滚和重新生成。
- 歌曲身份确认、平台映射修正、拆分和合并操作及审计。
- App AI 配置原协议复用：状态、八种协议、API、模型、模型列表、超时、请求头、Key 和用量限制。
- 内容生成策略：备用模型、提示词、结构版本、温度、Token 上限、重试、并发、限流、熔断、预算和发布门槛。
- 客户端配置：模块开关、轮询、缓存、版本、平台、地区、设备白名单、生效时间、灰度比例、版本哈希、验证、发布和回滚。
- App Agent 下发：音效调音、听歌洞察和每日问候均支持独立启停、提示词版本、系统提示词、用户模板、温度、最大输出 Token、最低超时和单次任务最大尝试；版本参与 App 本地缓存失效。
- 调音 Agent 技能下发：内置技能启停、自定义技能、技能 revision 与工具策略均进入版本化配置和公开 API；核心安全技能、`mono_audio_tuning` 单次强制调用和本地验证由服务端归一化保证。
- Agent 运行策略：三类 App Agent 共用可重试错误分类和指数退避；听歌洞察与每日问候在无效输出后先按策略重试，再使用本地可靠回退。
- 音乐幕后内容 Agent 会同时识别缺失栏目和有来源但明显过短的栏目，在预算允许时定向补全或增强，并只接受信息更完整的替换结果。
- App 冷启动、Token 生效和前台恢复时同步公开配置；详情页按内部歌曲 ID 缓存已发布内容并支持离线回退。
- HTTPS、现有 token-admin 挂载、健康检查、Prometheus 指标、备份和恢复脚本。

## 复用现有能力

- 相似歌曲和歌手其他歌曲继续使用 App 已接入的平台推荐接口，位于详情正文和来源之后。
- 管理登录、Token 校验、域名、证书、Nginx 和 PM2 继续使用现有 token-admin 体系。

## 仍受外部条件限制

- 生产资料采集适配器已接通 NCM 与 QCM。QSM、KCM 和 Apple Music 会先持久化客户端携带的具体平台歌曲快照；在服务端取得对应平台可信资料接口前，不会仅凭模型记忆编写故事。
- MFA、集中告警通知和外部不可篡改日志存储依赖现有账号平台和监控基础设施，当前服务提供 RBAC、审计日志、健康检查和指标接口。
- 未触发生产白名单歌曲生成，因此未产生模型费用，也未做真实内容的人工验收。
- 按需求方要求未运行 App/Xcode 构建。
